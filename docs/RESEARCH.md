## 项目族对照与裁剪

| 项目族 | 取舍与判别 |
| --- | --- |
| Windows 主基座 | **REUSE** ETW/WPR/WPA，xperf 用于历史 profile/已知工具链对照。系统会话能提供缓冲、文件和计数。核目标机 OS build、实际 WPT 套件、provider、架构、权限和会话冲突。ETW MCP 与 WPA MCP 可补已有 ETL 分析，前者为 headless，后者为早期预览，两者都留在工具层。 [ADK/WPT](https://learn.microsoft.com/en-us/windows-hardware/get-started/adk-install) · [ETW MCP](https://devblogs.microsoft.com/performance-diagnostics/etw-mcp-intro/) · [WPA MCP](https://devblogs.microsoft.com/performance-diagnostics/introducing-wpa-mcp-early-preview-of-ai-assisted-trace-analysis-in-windows-performance-analyzer/) |
| 现成采集/对照 | **REUSE** Procmon v4.13 作为覆盖有界的 oracle，对照过滤、事件属性、PML 和窗口。**ADAPT** pktmon 用于 Windows 报文/丢包特因，保留原 ETL、方向与转发节点，再派生 pcapng。**HOLD** Sysmon 常驻服务、dumpcap/Npcap 安装或分发。Sysmon 可消费已有配置的事件日志，pcap 单独保存五元组与网络时钟，进程归属走 ETW/连接生命周期。**HISTORICAL_LEAD** SilkETW v0.8（归档）仅参考 JSON 化，不能代原件。 [Procmon](https://learn.microsoft.com/sysinternals/downloads/procmon) · [pktmon](https://learn.microsoft.com/en-us/windows-server/networking/technologies/pktmon/pktmon) · [Sysmon](https://learn.microsoft.com/en-us/sysinternals/downloads/sysmon) · [dumpcap](https://www.wireshark.org/docs/man-pages/dumpcap.html) · [Npcap](https://npcap.com/guide/npcap-users-guide.html) · [SilkETW](https://github.com/mandiant/SilkETW/releases/tag/v0.8) |
| 分析/交换 | **REUSE** Perfetto TrackEvent、Trace Processor SQL/UI。**REFERENCE** Eclipse Trace Compass（EPL-2.0，CTF 和关联分析有优势）、Chrome Trace Event JSON（旧数据或简单演示）、OpenTelemetry（应用分布式 span、业务关联）。应用 span 只有已发出部分，内核时间、丢失和原件定位仍由传感器提供。 [Trace Compass](https://eclipse.dev/tracecompass/) · [Chrome 事件工具](https://www.chromium.org/developers/how-tos/trace-event-profiling-tool/) · [OpenTelemetry Trace API](https://github.com/open-telemetry/opentelemetry-specification/blob/main/specification/trace/api.md) |

| 插桩与应用 profiler | **ADAPT 候选** DynamoRIO（系统性短窗）和 Frida（特定 adapter）。**HOLD** Intel Pin（核具体 kit 的 OS/架构、许可与工具维护成本）。**REFERENCE** Tracy v0.15.0，适用己方可插桩代码的 CPU/GPU/锁等遥测，其 viewer 不增加闭源被测对象的可见面。.NET EventPipe 适合作为已有托管运行时诊断源，Windows 系统传感器仍以 ETW 为主。 [Intel Pin](https://www.intel.com/content/www/us/en/developer/articles/tool/pin-a-dynamic-binary-instrumentation-tool.html) · [Tracy v0.15.0](https://github.com/wolfpld/tracy/releases/tag/v0.15.0) · [EventPipe](https://learn.microsoft.com/en-us/dotnet/core/diagnostics/eventpipe) |

## 组合、语言与剩余未知

| 组合 | 复用与成立条件 |
| --- | --- |
| A．WPR/ETW + 薄控制器 + 离线 Perfetto | 优先验证。采集负载在 Windows 工具，应用负责小流量控制和导出。合成实证须判别 pre/post 覆盖、READY、失效/重叠 session、原件可读和事件时钟。若已满足合同，自有高频 ring 与高频回调的建设价值有限。 |
| B．owned ETW consumer + 同一离线 Perfetto | profile 级过滤、实时 marker 或 raw/loss 证据确需自控时再比。C# + TraceEvent 作为成熟对照，Rust + windows-rs/ferrisetw 与 C++ + SDK/krabsetw 同场对照。FFI、线程生命周期、异常/清理、位宽/构建发布在同一预算下验。 |
| C．持续 rolling + 有界触发和窄探针 | 有确切一次性事件需要前史时再论证。先复用 ETW/WPR 的 rolling 语义，证明保留窗、时间校准、触发后覆盖和 privacy budget。Stuttometer 仅提供设计参照。TTD、DynamoRIO 和 Frida 可分离为有明确问题的补充传感器。 |

当前工具链以公开可审阅版本为候选，Rust stable 1.100.0、TraceEvent 4.0.2、Windows SDK/ADK、CPython 3.14 系列的具体部署依赖均需锁到运行回执。Python 当前胶水及 Perfetto 离线 SQL 可继续复用。选型应由控制面是否满足合同、是否实际需要自有热路径以及 同条件测量决定。 [Rust 版本](https://github.com/rust-lang/rust/releases/tag/1.100.0) · [Python Windows 发布](https://www.python.org/downloads/windows/) · [Windows SDK](https://learn.microsoft.com/en-us/windows/apps/windows-sdk/)

**自研范围**包括录制生命周期、目标和会话身份、原件定位、时间与丢失出处、离线映射，以及按需验证的业务日志语义。系统缓冲和分析界面优先复用。

**待测项**包括 provider 源端过滤、QPC 与探针时钟对照、丢失分母、开销、ETL/PML 可读性和故障退出。详见 [验证计划](VALIDATION.md) 和 [Windows 研究](WINDOWS-FRONTIER.md)。
